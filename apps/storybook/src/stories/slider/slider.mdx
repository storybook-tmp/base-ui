# Slider

{/* BEGIN: anatomy */}

## Anatomy

```tsx
import { Slider } from '@base-ui/react/slider';

<Slider.Root>
  <Slider.Label />
  <Slider.Value />
  <Slider.Control>
    <Slider.Track>
      <Slider.Indicator />
      <Slider.Thumb />
    </Slider.Track>
  </Slider.Control>
</Slider.Root>;
```

| Part               | Renders                                 | Purpose                                            | Optional?           |
| :----------------- | :-------------------------------------- | :------------------------------------------------- | :------------------ |
| `Slider.Root`      | `<div>`, `role="group"`                 | Manages state                                      | required            |
| `Slider.Label`     | `<div>`                                 | Accessible label, auto-associated with every thumb | yes                 |
| `Slider.Value`     | `<output>`                              | Text readout of the current value(s)               | yes                 |
| `Slider.Control`   | `<div>`                                 | The tracked, clickable/draggable hit area          | required            |
| `Slider.Track`     | `<div>`                                 | Visual full-range bar                              | required            |
| `Slider.Indicator` | `<div>`                                 | Visual filled-portion bar                          | yes (purely visual) |
| `Slider.Thumb`     | `<div>` + nested `<input type="range">` | The draggable handle; one per value                | required (one+)     |

Minimal composition is `Root > Control > Track > (Indicator, Thumb)`. `Label` and `Value` are optional, but then the Thumb must carry its own `aria-label`.

## Keyboard & screen reader

| Key                                    | Context       | Action                                                                     |
| :------------------------------------- | :------------ | :------------------------------------------------------------------------- |
| ArrowUp / ArrowRight (flipped in RTL)  | Thumb focused | Increments by `step`; commits immediately                                  |
| ArrowDown / ArrowLeft (flipped in RTL) | Thumb focused | Decrements by `step`, symmetric                                            |
| Shift + arrow                          | Thumb focused | Steps by `largeStep`                                                       |
| Home / End                             | Thumb focused | Jumps to `min`/`max` (or adjacent thumb's value ± offset on range sliders) |
| PageUp / PageDown                      | Thumb focused | Steps by `largeStep` always, regardless of Shift                           |
| Tab / Shift+Tab                        | Thumb focused | Moves focus to the next/previous thumb, or out of the slider               |

- **The rendered role is the native, implicit `role="slider"` of `<input type="range">`, not a custom `div role="slider"` ARIA widget.** `getByRole('slider')` resolves to an `<input>` element throughout our test suite; `Root` itself renders `role="group"`, never `role="slider"`.
- **We chose the native input deliberately** (see the comment in `SliderThumb.test.tsx`): Android TalkBack's increase/decrease actions work on `input type="range"` via native change events, but not on pure ARIA implementations using `div role="slider"` (see the Chromium issue and mui/material-ui#23506 cited there). **The input element(s) must be the only focusable element(s).** A consumer inspecting the DOM expecting a styled `div[role=slider]` (as many other headless-slider libraries implement) will instead find a visually-hidden native `<input type="range">` doing the real work.
- `Slider.Value` renders `aria-live="off"` by default because a drag interaction would otherwise cause continuous, unhelpful announcements mid-gesture.
- **Known issues**: no open accessibility issues are known.
