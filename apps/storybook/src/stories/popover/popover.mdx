# Popover

{/* BEGIN: when-to-use */}

## When to use

- **Infotips**: essential info behind an info icon. Popups that open when hovering an info icon should use Popover with the `openOnHover` prop on the trigger instead of a tooltip, so touch users and screen reader users can access the content.
- **Description text too long for inline**: prefer inline text, or Popover if space is limited, so the information is accessible to everyone.
- **Interactive anchored panels**: notification inboxes (the hero above), filter and settings panels, link editors; also searched for as "Anchored Popup", "Floating Panel", "Info Box", or "Callout".
- **One shared popup for many triggers**: e.g. dozens of table rows each opening the same panel with per-row context; the detached-triggers + payload pattern exists for this ([#3577](https://github.com/mui/base-ui/issues/3577)).
- **A popover that must behave like a small modal**: block outside interaction while open via the `modal` prop, added on request ([#1459](https://github.com/mui/base-ui/pull/1459) closing [#623](https://github.com/mui/base-ui/issues/623)).
- **Hosting third-party widgets**: date pickers and similar commit-on-close panels are a recurring production pattern ([#10](https://github.com/mui/base-ui/issues/10)).

## When not to use

The core heuristic ([#3530](https://github.com/mui/base-ui/issues/3530)): a popover's trigger's purpose is to open the popover itself (and every platform is supported), while a tooltip's trigger's purpose is unrelated to the tooltip (and touch platforms are excluded).

Two questions decide it: **what is the trigger for**, and **may a touch user lose the content?** Tooltip and Preview Card are sighted-hover-only hints: they never show on touch (iOS has no OS tooltips; long-press conflicts with native context menus) and never receive focus. Popover is an anchored, non-modal-by-default mini-dialog: its content is essential or interactive, so every input modality can reach it and focus moves in.

|                             | [Tooltip](?path=/docs/overlays-tooltip--docs) | [Preview Card](?path=/docs/overlays-preview-card--docs) | Popover                         | [Dialog](?path=/docs/overlays-dialog--docs) |
| :-------------------------- | :-------------------------------------------- | :------------------------------------------------------ | :------------------------------ | :------------------------------------------ |
| Trigger's purpose           | its own action (the hint is a label)          | navigation (`<a>`)                                      | opening the popup itself        | opening the dialog                          |
| Opens on                    | hover/focus                                   | link hover                                              | click (+ optional hybrid hover) | click / imperative                          |
| Shown on touch              | **never**                                     | never                                                   | yes                             | yes                                         |
| Focus moves into popup      | never                                         | never                                                   | yes (except hover-open)         | yes                                         |
| Essential content allowed   | **no**                                        | no (must exist at the destination)                      | yes                             | yes                                         |
| Placement / `modal` default | anchored / n/a                                | anchored / n/a                                          | anchored / `false`              | centered / `true`                           |

- To show a **visual hint labeling a control that does something else**, use [Tooltip](?path=/docs/overlays-tooltip--docs), because tooltips are optional, sighted-only supplements ([#3530](https://github.com/mui/base-ui/issues/3530)).
- To preview a **link's destination on hover**, use [Preview Card](?path=/docs/overlays-preview-card--docs), because its trigger renders an `<a>` and the content must also exist at the destination.
- For **page-blocking flows or centered prompts**, use [Dialog](?path=/docs/overlays-dialog--docs), because it opens on top of the entire page, defaults to modal, and its handles support trigger-less `open()`. Popover's handle requires a `triggerId` because it needs an anchor ([#3065](https://github.com/mui/base-ui/pull/3065)). As a rule of thumb, use Popover when it must stay attached to what opened it, and Dialog when it should command the whole page.
- For an interruption **requiring a decision**, use [Alert Dialog](?path=/docs/overlays-alert-dialog--docs), because `role="alertdialog"` is always modal and refuses light dismiss ([#2146](https://github.com/mui/base-ui/issues/2146)).
- For an anchored **list of actions**, use [Menu](?path=/docs/overlays-menu--docs), because it provides `role="menu"`, roving highlight, and typeahead; a popover popup is a `dialog` with no item semantics. (Searches for "Popover Menu" or "Dropdown" often land here.)
- For **edge-anchored, gesture-dismissed panels**, use [Drawer](?path=/docs/overlays-drawer--docs): Drawer is edge-attached, swipe-dismissed, and page-scoped, while Popover stays anchored to its trigger. On small screens a desktop popover often becomes a drawer.
- For **pure hover reveal** of non-essential content, use Tooltip or Preview Card. We declined hover-only interactive popovers because hover-based UIs are not accessible; that is why the `openOnHover` prop is hybrid ([#2623](https://github.com/mui/base-ui/issues/2623)).

## Anatomy

```tsx
import { Popover } from '@base-ui/react/popover';

<Popover.Root>
  <Popover.Trigger />
  <Popover.Portal>
    <Popover.Backdrop />
    <Popover.Positioner>
      <Popover.Popup>
        <Popover.Arrow />
        <Popover.Viewport>
          <Popover.Title />
          <Popover.Description />
          <Popover.Close />
        </Popover.Viewport>
      </Popover.Popup>
    </Popover.Positioner>
  </Popover.Portal>
</Popover.Root>;
```

| Part                        | Renders    | Purpose                                                                                                                                                | Optional?                                                                            |
| :-------------------------- | :--------- | :----------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------------------------------------------------------------- |
| `Popover.Root`              | no element | Groups all parts; owns open state; accepts children as a node or `({ payload }) => ReactNode`                                                          | required                                                                             |
| `Popover.Trigger`           | `<button>` | Opens the popover; can live inside the Root or _outside_ it via `handle`; carries `openOnHover`/`delay`/`payload`                                      | required in practice (or drive open via handle/controlled state)                     |
| `Popover.Portal`            | portal     | Moves the popup subtree to `<body>` (or `container`); `keepMounted` lives here                                                                         | **required**; omitting it throws ([#1222](https://github.com/mui/base-ui/pull/1222)) |
| `Popover.Backdrop`          | `<div>`    | Styleable overlay beneath the popover                                                                                                                  | yes                                                                                  |
| `Popover.Positioner`        | `<div>`    | Positions the popup against the trigger; all position props (`side`, `align`, `anchor`, offsets) live here                                             | required                                                                             |
| `Popover.Popup`             | `<div>`    | `role="dialog"` container; owns `initialFocus`/`finalFocus`                                                                                            | required                                                                             |
| `Popover.Arrow`             | `<div>`    | Anchor pointer; `aria-hidden`; rotate via `data-side`                                                                                                  | yes                                                                                  |
| `Popover.Title`             | `<h2>`     | Labels the popup; wired to `aria-labelledby`                                                                                                           | yes (recommended)                                                                    |
| `Popover.Description`       | `<p>`      | Supporting text; wired to `aria-describedby`                                                                                                           | yes                                                                                  |
| `Popover.Close`             | `<button>` | Closes the popover; **required inside the Popup for modal focus trapping** (may be visually hidden, [#4084](https://github.com/mui/base-ui/pull/4084)) | yes otherwise                                                                        |
| `Popover.Viewport`          | `<div>`    | Content-transition container; only needed when one popup serves multiple triggers with animated content swaps                                          | yes                                                                                  |
| `Popover.createHandle<P>()` | —          | Factory returning a `PopoverHandle`: connect detached triggers and Roots; imperative `open(triggerId)`/`close()`                                       | yes                                                                                  |

Notes: rendering without `Portal` caused various bugs, so we restricted the API to require it; the only loss is popup content in server-rendered HTML, which isn't supported ([#4750](https://github.com/mui/base-ui/issues/4750)). Nested popovers auto-join the parent's floating tree and portal, so set a custom `container` only on the root Portal ([#1930](https://github.com/mui/base-ui/issues/1930)). When using `Viewport`, freeze the Positioner to `var(--positioner-width/height)` during transitions, because content-driven resizing can make the popup thrash or flip sides.

## Related

- To label a control whose **own action** is the point, use [Tooltip](?path=/docs/overlays-tooltip--docs), a sighted-hover-only hint.
- To preview a **link** on hover, use [Preview Card](?path=/docs/overlays-preview-card--docs).
- To command the **whole page**, use [Dialog](?path=/docs/overlays-dialog--docs); for interruptions requiring a decision, [Alert Dialog](?path=/docs/overlays-alert-dialog--docs).
- To show an anchored list of **actions**, use [Menu](?path=/docs/overlays-menu--docs).
- For **edge-anchored, gesture-dismissed** panels, use [Drawer](?path=/docs/overlays-drawer--docs).
