{/* BEGIN: general */}
Provides a shared state to a series of toggle buttons.

- **Import:** `import { ToggleGroup } from '@base-ui/react/toggle-group';`
- **Parts:** 1 at the export surface. There is no `ToggleGroup.Item`; items are plain [Toggle](?path=/docs/actions-toggle--docs) components.
- **Status:** Stable. Introduced jointly with Toggle in a single PR ([#763](https://github.com/mui/base-ui/pull/763)).
- **ARIA pattern:** closest to the roving-tabindex mechanics of the [Toolbar](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/) pattern, layered under `role="group"`; item-level semantics follow the [Toggle Button](https://www.w3.org/WAI/ARIA/apg/patterns/button/#toggle_button) pattern.

<Canvas of={ToggleGroupStories.Hero} />

## Features

- **Deselectable single-select mode**: pressing the currently-pressed item again clears the selection to nothing, unlike a radio group.
- **`multiple` mode**: items become independently toggleable (bold/italic/underline).
- **Toolbar-aware**: detects a hosting `Toolbar.Root` via context and defers its entire composite/roving-focus behavior to the Toolbar's own `CompositeRoot` instead of creating its own.
- **Full composite keyboard contract when standalone**: single Tab stop, arrow-key roving focus with looping, and Home/End support.

## How it works

### `multiple` and selection semantics

In `multiple` mode, pressing an item toggles it independently of its siblings. In single mode (`multiple={false}`, the default), pressing an item replaces the whole selection with either `[value]` or `[]`, so single mode _is_ deselectable to empty. That property is what distinguishes it from RadioGroup.

### Composite keyboard navigation

A standalone `ToggleGroup` wraps its own `CompositeRoot`: the group is a single Tab stop, arrow keys move roving focus among items (wrapping at the ends when `loopFocus`, the default), and Home/End jump to the first/last item.

**Toolbar-hosted asymmetry:** when a `ToggleGroup` is nested inside a `Toolbar.Root`, it renders a plain `role="group"` div and defers its roving-focus behavior entirely to the _Toolbar's_ own `CompositeRoot`, which never enables Home/End. This means Home/End work standalone (as shown below) but **not** when the same group is hosted inside a Toolbar ([#3971](https://github.com/mui/base-ui/pull/3971) added Home/End to ToggleGroup's own composite root; it could not retrofit Toolbar's separate one). See the [Toolbar](?path=/docs/actions-toolbar--docs) stories for the hosted case.

The Toolbar-hosted case, shown side by side with the standalone one above: arrow keys still rove focus, but Home/End are no-ops.

### Disabled cascade

`disabled` on the Root cascades to every child Toggle; an individually `disabled` Toggle is additionally skipped by roving focus while its enabled siblings remain reachable.

## Choosing the right props

- **`multiple`** (default `false`): set `true` when items are independently toggleable (bold/italic/underline); leave `false` for exclusive-with-clear (alignment, view mode).
- **`value`/`defaultValue`/`onValueChange`**: always array-shaped, even in single mode. Use controlled `value` when the selection must be driven or synced from outside.
- **`loopFocus`** (default `true`): set `false` if wrap-around arrow navigation at the ends is undesired.
- **`disabled`**: cascades to every child Toggle; combines with a hosting Toolbar's own cascading `disabled` when nested.
