# Tabs

{/* BEGIN: anatomy */}

## Anatomy

```tsx
import { Tabs } from '@base-ui/react/tabs';

<Tabs.Root>
  <Tabs.List>
    <Tabs.Tab />
    <Tabs.Indicator />
  </Tabs.List>
  <Tabs.Panel />
</Tabs.Root>;
```

| Part             | Renders    | Purpose                                                  | Optional?          |
| :--------------- | :--------- | :------------------------------------------------------- | :----------------- |
| `Tabs.Root`      | `<div>`    | Groups the tabs and the corresponding panels             | required           |
| `Tabs.List`      | `<div>`    | Groups the individual tab buttons; `role="tablist"`      | required           |
| `Tabs.Tab`       | `<button>` | An individual tab that toggles the corresponding panel   | required, repeated |
| `Tabs.Indicator` | `<span>`   | A visual indicator that tracks the active tab's position | optional           |
| `Tabs.Panel`     | `<div>`    | Displayed when the corresponding tab is active           | required, repeated |

Panels are **not** children of `List`. They are siblings of `List` under `Root`, matched to tabs purely by `value`, not DOM position. There is no Portal/Positioner/Popup: Tabs renders in normal document flow.

## Decision log

- **2024-04-29: Tabs API overhaul** ([#245](https://github.com/mui/base-ui/pull/245)): replaced the Material-UI-era slots API with the render prop; renamed `selectionFollowsFocus` to `activateOnFocus` and moved it from Root to List; added `loop` and `keepMounted`. This PR is also where the activation-direction CSS attribute contract (`data-activation-direction`, normalized `up|down|right|left`) took its current shape during review.
- **2024-11-25: Modernize implementation** ([#751](https://github.com/mui/base-ui/pull/751)): rewired Tabs onto the shared `Composite` internals also used by Menu/Toolbar/RadioGroup.
- **Change `activateOnFocus` to false** ([#3176](https://github.com/mui/base-ui/pull/3176)): the central accessibility-policy decision for this component. Default activation timing flipped from activating on focus/mousedown to activating on click only; we chose WCAG 2.5.2 pointer-cancellation conformance over the more responsive feel of focus-driven activation. Opting into `activateOnFocus={true}` restores immediate focus-driven activation, with a main-button gate for mouse-originated focus.
