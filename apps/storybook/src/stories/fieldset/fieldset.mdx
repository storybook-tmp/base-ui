# Fieldset

{/* BEGIN: anatomy */}

## Anatomy

```tsx
import { Fieldset } from '@base-ui/react/fieldset';

<Fieldset.Root>
  <Fieldset.Legend />
</Fieldset.Root>;
```

| Part              | Renders      | Purpose                                                  |
| :---------------- | :----------- | :------------------------------------------------------- |
| `Fieldset.Root`   | `<fieldset>` | The native grouping boundary; carries `disabled` cascade |
| `Fieldset.Legend` | `<div>`      | The stylable label, auto-linked via `aria-labelledby`    |

{/* END: anatomy */}

{/* BEGIN: history */}

## Decision log

- **`Fieldset.Legend` renders a `<div>`, not a native `<legend>`** ([#3044](https://github.com/mui/base-ui/issues/3044), closed): `<legend>` elements are hard to style and position and don't act like regular flow elements. Using `div` + `aria-labelledby` avoids the styling issues and minimizes the a11y issues (see [adrianroselli.com's `<legend>` bug research](https://adrianroselli.com/2022/07/use-legend-and-fieldset.html#Bugs)).

{/* END: history */}

## Known issues & open questions

- **[#3930](https://github.com/mui/base-ui/issues/3930)** ("Investigate `Fieldset`s as validation boundaries", open): today, a group of _non-identical_ controls gets its validation boundary from an outer `Field.Root` wrapping the whole `Fieldset.Root` (`<Field.Root><Fieldset.Root>...</Fieldset.Root></Field.Root>`), while _identical_ repeated controls (radio/checkbox groups) each get their own `Field.Item` inside the Fieldset. We flagged this asymmetry as worth reconsidering: possibly making `Fieldset.Root` itself the validation boundary directly, with one `Field.Root` per repeated control nested _inside_ it instead. **Treat this as unresolved, not settled behavior.**
- **[#3260](https://github.com/mui/base-ui/issues/3260)** (open): `Fieldset.Description`/`Fieldset.Error` parts requested; Fieldset ships with exactly 2 parts today. Group-level description/error text has no dedicated part; author it manually or rely on per-item `Field.Description`/`Field.Error`.
- **[#3262](https://github.com/mui/base-ui/issues/3262)** (open): `useFieldsetRootContext` is not publicly exported; consumers can't read Fieldset's `disabled` state the sanctioned way. `data-disabled` is the escape hatch today.
