## When to use

- Showing a preview of what a **link** points to before the user commits to navigating. The canonical examples are Wikipedia-style article previews and GitHub-style profile/PR hover previews, the real-world precedent this component follows ([#4170](https://github.com/mui/base-ui/issues/4170), [#4778](https://github.com/mui/base-ui/issues/4778)).
- Multiple links on a page that should each preview differently, optionally sharing one popup instance via a `handle` for DOM-reuse.
- When the destination page is itself the source of truth for everything in the preview: the popup is a convenience peek, never a place to put facts the user can only get by hovering.

## When not to use

Both Tooltip and Preview Card are hover/focus-only and sighted-only, never move focus into themselves, and never open on touch. The dividing line is the **trigger's element and purpose**: the pattern is intended for links only, in both Base UI and Radix ([#4778](https://github.com/mui/base-ui/issues/4778)). If you're not rendering a link, you should not use Preview Card; Popover with `openOnHover` might be a good fit, depending on your use case.

- **Preview Card's trigger is a link whose purpose is navigation**: the popup exists to preview _where that link goes_ before the user commits to leaving the page.
- **[Tooltip](?path=/docs/overlays-tooltip--docs)'s trigger is typically a non-link control** (a button/icon) whose purpose is unrelated to the tooltip content. The tooltip is a label for a tool, not the point of interacting with the trigger.
- If touch/keyboard/screen-reader access to the content is **required**, use [Popover](?path=/docs/overlays-popover--docs) with `openOnHover` instead. Popover supports every input modality and moves focus in; Preview Card by design never does either. We closed both [#4170](https://github.com/mui/base-ui/issues/4170) and [#4778](https://github.com/mui/base-ui/issues/4778) by pointing to alternatives rather than changing the accessibility model.

The litmus test: if you're not rendering a link, you should not use Preview Card.

## Anatomy

```tsx
import { PreviewCard } from '@base-ui/react/preview-card';

<PreviewCard.Root>
  <PreviewCard.Trigger />
  <PreviewCard.Portal>
    <PreviewCard.Backdrop />
    <PreviewCard.Positioner>
      <PreviewCard.Popup>
        <PreviewCard.Arrow />
        <PreviewCard.Viewport />
      </PreviewCard.Popup>
    </PreviewCard.Positioner>
  </PreviewCard.Portal>
</PreviewCard.Root>;
```

| Part                            | Renders    | Purpose                                                                                                       | Optional?            |
| :------------------------------ | :--------- | :------------------------------------------------------------------------------------------------------------ | :------------------- |
| `PreviewCard.Root`              | no element | Groups all parts; owns open state                                                                             | required             |
| `PreviewCard.Trigger`           | `<a>`      | A link that opens the preview card; carries `delay`/`closeDelay`/`payload`                                    | required in practice |
| `PreviewCard.Portal`            | portal     | Moves the popup subtree to `<body>`; required for the popup to render at all                                  | required             |
| `PreviewCard.Backdrop`          | `<div>`    | Presentational overlay beneath the popup; a sibling of Positioner, not a wrapper around it                    | yes                  |
| `PreviewCard.Positioner`        | `<div>`    | Positions the popup against the trigger                                                                       | required             |
| `PreviewCard.Popup`             | `<div>`    | Container for the preview card contents; carries no ARIA role                                                 | required             |
| `PreviewCard.Arrow`             | `<div>`    | Visual pointer at the anchor                                                                                  | yes                  |
| `PreviewCard.Viewport`          | `<div>`    | Content-transition container; only needed when one popup serves multiple triggers with animated content swaps | yes                  |
| `PreviewCard.createHandle<P>()` | —          | Factory returning a handle: connect detached triggers and Roots                                               | yes                  |

**No `Provider` part exists**. If a page has ten Preview Card triggers, hovering the second one within the first one's close-delay window does not get a shortened/instant open the way grouped tooltips do. Each `PreviewCard.Root` (or handle-backed cluster) tracks its own delay state independently.

## Related

- To label a control whose **own action** is the point, use [Tooltip](?path=/docs/overlays-tooltip--docs): a sighted-hover-only hint, no link required.
- For **essential or interactive** anchored content reachable by every modality, use [Popover](?path=/docs/overlays-popover--docs) with `openOnHover`.
