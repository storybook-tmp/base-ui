# Separator

{/* BEGIN: when-to-use */}

## When to use

- Dividing groups of items in menus/select/combobox/autocomplete/context-menu listboxes: the dominant use case; 6 of 7 known consuming components are list/menu-shaped selection surfaces that re-export `Separator` directly between `Group`s.
- Dividing toolbar sections via `Toolbar.Separator`, between logical button/control clusters.
- Chunking a single field's inputs visually with `OTPField.Separator`, e.g. presenting a code as `123-456`.
- General standalone content/nav dividers. The hero demo above shows a vertical separator between two clusters of navigation links.

## When not to use

- For a purely decorative visual line with no semantic grouping meaning: `Separator` renders `role="separator"` **unconditionally**, with no built-in "presentational" escape hatch. For a zero-behavior ornamental line, a plain styled `<div>`/border avoids pulling in a component for no behavioral gain.
- Native `<hr>` is a reasonable alternative for simple horizontal-only, non-orientable dividers outside a Base UI compound component; it already carries correct implicit ARIA separator semantics. `Separator` earns its keep for vertical orientation, the `render` polymorphic escape hatch, and compound-component re-export convenience.

{/* END: when-to-use */}

{/* BEGIN: anatomy */}

## Anatomy

```tsx
import { Separator } from '@base-ui/react/separator';

<Separator />;
```

Renders a single `<div>` with no sub-parts and no required children. The consumer sizes/styles it (width/height via CSS) to read visually as a line.

{/* END: anatomy */}
