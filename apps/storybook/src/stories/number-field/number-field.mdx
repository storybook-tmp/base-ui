A numeric input element with increment and decrement buttons, and a scrub area.

- **Import:** `import { NumberField } from '@base-ui/react/number-field';`
- **Parts:** 7 (`NumberField.Root`, `Group`, `Input`, `Increment`, `Decrement`, `ScrubArea`, `ScrubAreaCursor`).
- **Status:** Stable. One of Base UI's three founding components (alpha.0, April 2024, PR [#186](https://github.com/mui/base-ui/issues/186)), continuously maintained. A run of 2026 parsing/formatting correctness fixes shows the format pipeline is still under active development.
- **ARIA pattern:** No dedicated APG pattern is implemented (see below). The closest named pattern is [Spinbutton](https://www.w3.org/WAI/ARIA/apg/patterns/spinbutton/), which this component does **not** use by design.

<Canvas of={NumberFieldStories.Hero} />

## Features

- **Typed, formatted numeric entry first, stepping as an enhancement**: the visible `Input` renders `type="text"`, not `type="number"`, so `Intl.NumberFormat`-quality display (currency, percent, units, grouping) can be shown and edited; a hidden `<input type="number">` carries native constraint validation and form submission, decoupled from the formatted text.
- **Two change callbacks**: `onValueChange` fires on every parseable intermediate change; a separate `onValueCommitted` fires only once a value is finalized (blur, pointer release, or immediately for keyboard steps). The split is easy to misread as redundant.
- **A scrub area for pointer users**: click-and-drag anywhere in `ScrubArea` to change the value continuously, with a portaled virtual cursor (`ScrubAreaCursor`) replacing the OS cursor during the gesture. Fully optional; both parts render `role="presentation"`.
- **Locale- and format-aware**: `format` (raw `Intl.NumberFormatOptions`) and `locale` control currency, percent, unit, and numeral-system display without a separate parsing layer to maintain yourself.

## When to use

- Any numeric value that benefits from formatted display (currency, percent, units) alongside typed entry and click-to-step controls. The `parse.ts`/`validate.ts`/`formatNumber` pipeline exists for this.
- Forms needing native constraint validation (`min`/`max`/`step`/`required`) on a numeric field, where the formatted display must never pollute the submitted value.
- A bounded, steppable range where increment/decrement affordances and/or drag-to-scrub add value beyond free-text entry.
- Likely real-world archetypes (checkout quantity fields, currency settings panels) are plausible, with no known public examples beyond what's in "In the wild" below.

## When not to use

- For continuous/glanceable range selection where exact typed precision matters less than position-relative-to-bounds, prefer [Slider](?path=/docs/form-inputs-slider--docs): its primary interaction is the drag gesture itself, with no typed-entry path at all.
- For plain unformatted numeric entry with no locale/formatting/stepping need, a bare `Input` (or native `<input type="number">`) is lower overhead.
- Not for math-expression evaluation (`"5+20"`). We declined this direction and suggested a separate component instead (mui/base-ui#2152).

## How it works

### `onValueChange` vs `onValueCommitted`

The key behavioral contract is that `onValueChange(value, eventDetails)` fires on every parseable intermediate change (each keystroke that parses, each step). A separate `onValueCommitted(value, eventDetails)` fires only when a value is finalized: on blur after typing, on pointer release after scrubbing/button-press, or simultaneously with `onValueChange` for keyboard/wheel interactions. `onValueCommitted` is a generic event, not a change event; only `onValueChange`'s `eventDetails.cancel()` can veto a change.

### Keyboard stepping

Arrow keys step by `step` (default `1`); Shift multiplies to `largeStep` (default `10`); Alt uses `smallStep` (default `0.1`). Home/End jump directly to `min`/`max`, but **only when those props are set**; otherwise the browser's native text-caret Home/End behavior takes over instead.

**PageUp/PageDown stay native**: the key handling falls through to native browser behavior for PageUp/PageDown, diverging from the ARIA spinbutton pattern's optional PageUp/PageDown-as-large-step convention. Consistent with the ARIA choice below, this component never adopted that pattern.

### The scrub area

Click-and-drag anywhere in `ScrubArea` to change the value continuously (pointer lock, outside Safari/WebKit, which we exclude to avoid a native layout-shifting notification). **This story renders and describes the gesture rather than driving it with a play function**: real OS-level pointer lock is denied or inconsistent in headless browser automation, and our own `NumberFieldScrubArea.test.tsx` skips both JSDOM and WebKit for the same reason.

### min / max / step

`step` (default `1`) governs stepping; unset `min`/`max` default internally to `Number.MIN_SAFE_INTEGER`/`MAX_SAFE_INTEGER`, but the _native_ hidden input only receives the literal `min`/`max` passed in, which matters for native `stepMismatch`/`rangeOverflow` validity.

### Form integration

The story applies `noValidate` on the surrounding `<form>` deliberately, because the default `step={1}` triggers native step validation once an explicit `min` is present, and forms that skip `noValidate` can have submission silently blocked by a native browser popup the developer didn't expect (mui/base-ui#3552, a confirmed shadcn/RHF-forms pitfall). Base UI's `Field`/`Form` validation is meant to be authoritative instead.

### Press-and-hold stepping

Holding `pointerdown` on a stepper button performs one immediate step, then (after `START_AUTO_CHANGE_DELAY`, 400ms) starts continuous auto-repeat every `CHANGE_VALUE_TICK_DELAY` (60ms). A single `onValueCommitted` fires on pointer release (never once per tick), and the auto-repeat halts on its own at the `max`/`min` boundary, well before release.

### `onValueChange` vs `onValueCommitted`, made observable

Two live counters make the two-callback split directly observable: typing digits fires `onValueChange` once per keystroke but `onValueCommitted` only once, on blur; a stepper click fires both exactly once, together.

### `snapOnStep`

Snaps increment/decrement results to the nearest multiple of `step` (directional snapping toward the direction of travel), contrasted with the exact-step behavior when the prop is unset.

### `allowOutOfRange`

By default, typed values are clamped to `min`/`max` immediately at the numeric-value level (visible on the hidden native input); the displayed text itself only resyncs to the clamped value on blur. With `allowOutOfRange`, direct text entry can exceed the bounds entirely so the native `rangeOverflow`/`rangeUnderflow` validity becomes reachable. Stepper-button and keyboard stepping still clamp regardless of the prop.

### Locale and currency formatting

`format` (raw `Intl.NumberFormatOptions`) and `locale` drive the displayed text through the standard `Intl.NumberFormat` pipeline, while the value submitted to a form stays a plain number. Not covered by an existing docs demo.

### Wheel scrubbing

With `allowWheelScrub`, each discrete wheel tick over the focused `Input` steps the value by one `step` and commits immediately, distinct from the accumulating drag gesture in `ScrubArea`. `ctrlKey` wheel events (pinch-zoom) are ignored.

### `Field` integration

Wrapping in `Field.Root` with a `validate` function shows how validation state attributes are duplicated: `data-valid`/`data-invalid`/`data-touched`/`data-dirty`/`data-filled`/`data-focused` appear on every part (Root, Group, Input, Increment, Decrement) simultaneously, since they all share one `state` object.

### Disabled and read-only

`disabled` removes the field from interaction and native form submission entirely: the hidden input itself becomes `disabled`. `readOnly` keeps the `Input` focusable and copyable but blocks edits, and disables the stepper buttons via computed `disabled` rather than `aria-readonly` (invalid on `role="button"`).

## Keyboard & screen reader

| Key                                                                                       | Context                        | Action                                                                              |
| :---------------------------------------------------------------------------------------- | :----------------------------- | :---------------------------------------------------------------------------------- |
| Any numeral / decimal / group / sign / currency / unit / percent symbol the format allows | Input focused                  | Typed directly; parseable intermediate values fire `onValueChange` (`input-change`) |
| ArrowUp / ArrowDown                                                                       | Input focused                  | Steps by `step` (Shift → `largeStep`, Alt → `smallStep`); commits immediately       |
| Home / End                                                                                | Input focused, `min`/`max` set | Jumps to `min`/`max`; commits immediately. No-op (native caret behavior) when unset |
| PageUp / PageDown                                                                         | Input focused                  | **Not implemented**; falls through to native browser handling                       |
| Backspace / Delete / ArrowLeft / ArrowRight / Tab / Enter / Escape                        | Input focused                  | Native text-editing/navigation, explicitly passed through                           |
| Click-drag on ScrubArea                                                                   | Pointer down                   | Continuous stepping proportional to movement; pointer-only                          |

- **ARIA**: the Input does **not** use `role="spinbutton"`; there is no `aria-valuenow`/`aria-valuemin`/`aria-valuemax`/`aria-valuetext` anywhere. It is a plain implicit `role="textbox"` (our tests query `getByRole('textbox')` throughout). It additionally carries `aria-roledescription="Number field"`, a role _description_, not an accessible name; use `Field.Label`/`aria-label` for that.
- This was a considered decision: the founding PR [#186](https://github.com/mui/base-ui/issues/186) left researching whether spinbutton ARIA props become necessary for iOS as an open checklist TODO; the shipped component never added them, and no later PR reversed that. The likely rationale: a spinbutton's `aria-valuenow`/`aria-valuetext` model fits a value that's _set_, whereas this component's primary interaction is free-form formatted text editing where the visible text should simply be read like any other text input.
- **Known issues**: [#4226](https://github.com/mui/base-ui/issues/4226) (open) reports that `min`/`max` are not reflected as native `min`/`max` attributes on the `type="text"` input, which limits what screen readers can announce about the accepted range.

## Choosing the right props

- **`format` / `locale`**: the formatting surface is delegated to standard `Intl.NumberFormatOptions`; combine with `locale` to vary independently.
- **`allowOutOfRange`**: lets _direct text entry only_ (typing/paste/clear/autofill) exceed `min`/`max` so native range-overflow validation can fire; step-based interactions (arrows, buttons, wheel, scrub) always clamp regardless.
- **`snapOnStep`**: snaps increment/decrement results to the nearest multiple of `step`, using directional snapping for regular steps and nearest-multiple snapping for Alt/`smallStep` moves.
- **`allowWheelScrub`**: one step per discrete wheel tick while the input is focused; distinct from the accumulating drag-based `ScrubArea` gesture. Ignores `ctrlKey` wheel events (pinch-zoom) so it doesn't hijack browser zoom.

## Do / Don't

**Do**

- Add `noValidate` to the surrounding `<form>` if you want Base UI's own `Field`/`Form` validation to be authoritative over native `step`/`min` constraint popups (mui/base-ui#3552).
- Read the `onValueChange`/`onValueCommitted` split together; they are not redundant names for the same event.

**Don't**

- Don't expect `role="spinbutton"` or `aria-valuenow`; both are absent by design.
- Don't expect PageUp/PageDown to large-step; only Home/End (when bounds are set) and Shift+Arrow do.
