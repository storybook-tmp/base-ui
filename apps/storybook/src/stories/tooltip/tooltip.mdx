## Anatomy

```tsx
import { Tooltip } from '@base-ui/react/tooltip';

<Tooltip.Provider>
  <Tooltip.Root>
    <Tooltip.Trigger />
    <Tooltip.Portal>
      <Tooltip.Positioner>
        <Tooltip.Popup>
          <Tooltip.Arrow />
          <Tooltip.Viewport />
        </Tooltip.Popup>
      </Tooltip.Positioner>
    </Tooltip.Portal>
  </Tooltip.Root>
</Tooltip.Provider>;
```

| Part                        | Renders    | Purpose                                                                                                             | Optional?            |
| :-------------------------- | :--------- | :------------------------------------------------------------------------------------------------------------------ | :------------------- |
| `Tooltip.Provider`          | no element | Shares a delay/`FloatingDelayGroup` across sibling `Root`s so adjacent tooltips open near-instantly after the first | yes                  |
| `Tooltip.Root`              | no element | Groups all parts; owns open state                                                                                   | required             |
| `Tooltip.Trigger`           | `<button>` | The element the tooltip attaches to; may be "contained" (inside Root) or "detached" (anywhere, via `handle`)        | required in practice |
| `Tooltip.Portal`            | portal     | Moves the popup subtree to `<body>`; **required**: the parts below throw if used outside it                         | required             |
| `Tooltip.Positioner`        | `<div>`    | Positions the popup against the trigger                                                                             | required             |
| `Tooltip.Popup`             | `<div>`    | Container for the tooltip contents                                                                                  | required             |
| `Tooltip.Arrow`             | `<div>`    | Visual pointer at the anchor                                                                                        | yes                  |
| `Tooltip.Viewport`          | `<div>`    | Content-transition container; only needed when one popup serves multiple triggers with animated content swaps       | yes                  |
| `Tooltip.createHandle<P>()` | —          | Factory returning a handle: connect detached triggers and Roots; imperative control                                 | yes                  |

## Brand guidelines

**Do**

- Use the lighter lift shadow and card radius — Droppy has no tooltip pattern; this is the recorded interpretation. (BR-06, BR-11)
- Write tooltip copy in sentence case, short and direct. (BR-08)

**When to use**

- Tooltips are near-absent from the brand by design: Droppy's calm, accessibility-first brand favors visible labels over hover-only affordances, and Base UI's Tooltip is sighted-pointer-only — no touch, no reliable exposure to assistive tech — so it must never carry information the interface needs to work (the same "never rely on color alone" reasoning applies to hover).
- Do reach for a Tooltip only on icon-only controls where a visible label can't fit (e.g. a theme toggle), with copy in sentence case matching the accessible name. (BR-08)
- Don't use a Tooltip to deliver essential content — give it a visible label, or use Popover instead.
