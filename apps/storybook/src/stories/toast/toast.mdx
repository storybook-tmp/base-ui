# Toast

{/* BEGIN: anatomy */}

## Anatomy

```tsx
import { Toast } from '@base-ui/react/toast';

<Toast.Provider timeout={5000} limit={3}>
  {/* app — anywhere below, useToastManager() can add toasts */}
  <Toast.Portal>
    <Toast.Viewport>
      {toasts.map((toast) => (
        <Toast.Root key={toast.id} toast={toast}>
          <Toast.Content>
            <Toast.Title />
            <Toast.Description />
            <Toast.Action />
            <Toast.Close />
          </Toast.Content>
        </Toast.Root>
      ))}
    </Toast.Viewport>
  </Toast.Portal>
</Toast.Provider>;
```

| Part                         | Renders              | Purpose                                                                                                                                                                   | Optional?                                                                     |
| :--------------------------- | :------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | :---------------------------------------------------------------------------- |
| `Toast.Provider`             | no element           | Owns the `ToastStore` (timers, stack order, hover/focus state); accepts `timeout`, `limit`, `toastManager`                                                                | required                                                                      |
| `Toast.Portal`               | `<div>`              | Moves the viewport to `<body>` (or `container`)                                                                                                                           | required for the viewport ([#1962](https://github.com/mui/base-ui/pull/1962)) |
| `Toast.Viewport`             | `<div>`              | `role="region"`, `aria-label="Notifications"`, and the polite `aria-live` container itself; the F6 focus target                                                           | required                                                                      |
| `Toast.Root`                 | `<div>`              | Groups one toast; `role="dialog"` (or `"alertdialog"` for `priority: 'high'`); hosts the swipe engine; requires the `toast` prop                                          | required, one per rendered toast                                              |
| `Toast.Content`              | `<div>`              | Measures natural height (Resize/MutationObserver); carries `data-behind`/`data-expanded` for variable-height stacking ([#2742](https://github.com/mui/base-ui/pull/2742)) | optional for non-stacked/always-expanded designs                              |
| `Toast.Title`                | `<h2>`               | Labels the toast; defaults children to `toast.title`; renders nothing without content                                                                                     | yes                                                                           |
| `Toast.Description`          | `<p>`                | Describes the toast; defaults to `toast.description`; renders nothing without content                                                                                     | yes                                                                           |
| `Toast.Action`               | `<button>`           | Performs an action; children/props default from `toast.actionProps`; renders nothing without content                                                                      | yes                                                                           |
| `Toast.Close`                | `<button>`           | Closes this toast; `aria-hidden` while the viewport is neither expanded nor focused                                                                                       | yes, but required in practice so users can dismiss persistent toasts          |
| `Toast.Positioner`           | `<div>`              | Anchored positioning (side/align/offsets/collision) for one toast, via own props or `toast.positionerProps`                                                               | anchored toasts only ([#3096](https://github.com/mui/base-ui/pull/3096))      |
| `Toast.Arrow`                | `<div>`              | Points toward the anchor                                                                                                                                                  | anchored toasts only                                                          |
| `Toast.useToastManager()`    | hook (no element)    | Returns `{ toasts, add, update, close, promise }` from inside a `Provider`                                                                                                | required to create toasts from a component                                    |
| `Toast.createToastManager()` | factory (no element) | Same surface, callable from outside React; pass the instance to `<Toast.Provider toastManager>`                                                                           | for module-scope/non-React callers                                            |

The render loop over `toasts` is entirely yours; there is no automatic renderer. Every story below wraps its content in a shared `ToastDemoShell` that composes `Provider > Portal > Viewport` and maps `useToastManager().toasts`.

## Decision log

- **2025-04-08**: Component introduced, [#1467](https://github.com/mui/base-ui/pull/1467), closing [#220](https://github.com/mui/base-ui/issues/220). Goals in the PR body: swipe, stack, global queue. `useToast` renamed `useToastManager` in review to match the global API. Shipped in v1.0.0-alpha.8.
- **2025-05**: `Portal` part added ([#1962](https://github.com/mui/base-ui/pull/1962)); limited toasts stay in the DOM with `inert` instead of being removed ([#1953](https://github.com/mui/base-ui/pull/1953)).
- **2025-07**: Viewport becomes the announce container ([#2246](https://github.com/mui/base-ui/pull/2246)): removes the per-toast hidden announcer, adds the separate hidden `role="alert"` container for high priority, makes `Toast.Close` `aria-hidden` when not expanded.
- **2025-09**: Variable-height stacking + new `Toast.Content` part ([#2742](https://github.com/mui/base-ui/pull/2742), closing [#1955](https://github.com/mui/base-ui/issues/1955)); `title`/`description` widen to `ReactNode` ([#2929](https://github.com/mui/base-ui/pull/2929)).
- **2025-10/11**: Anchored toasts: Positioner + Arrow parts, `positionerProps` on `add()` ([#3096](https://github.com/mui/base-ui/pull/3096), closing [#3026](https://github.com/mui/base-ui/issues/3026)).
- **2026-01→03**: Manager API maturation: generics `useToastManager<Data>`/`createToastManager<Data>` ([#3882](https://github.com/mui/base-ui/pull/3882)); `close()` with no id closes all ([#3979](https://github.com/mui/base-ui/pull/3979), Sonner/Chakra `dismiss` precedent); timer rescheduling on update fixed ([#3564](https://github.com/mui/base-ui/pull/3564)).
- **2026-03→05**: Dedup/upsert via `add({ id })` + `updateKey` counter ([#4440](https://github.com/mui/base-ui/pull/4440), from [#4228](https://github.com/mui/base-ui/issues/4228)); timers resume after window refocus ([#4438](https://github.com/mui/base-ui/pull/4438)).
- **Manager pattern stays toast-only**: we declined the same imperative-manager API for Dialog ([#2802](https://github.com/mui/base-ui/issues/2802)), because toasts have a simple render structure where a hook passing the data payload works well; Dialog uses `createHandle()` instead.
- **2026-06**: `focus` option rejected ([#4533](https://github.com/mui/base-ui/pull/4533)): toasts must not move focus; AlertDialog is the alternative. Companion docs fix: undo demo timeout raised to 10s ([#4975](https://github.com/mui/base-ui/pull/4975)). Open counterparts: [#4253](https://github.com/mui/base-ui/issues/4253) (a11y timing), [#4229](https://github.com/mui/base-ui/issues/4229) (a11y guide).

## Known issues & open questions

- [#4253](https://github.com/mui/base-ui/issues/4253) (open): keyboard/screen-reader users can't reach an Undo action before dismissal; no built-in fix is planned, and the documented mitigation is long timeouts.
- [#4229](https://github.com/mui/base-ui/issues/4229) (open): no usage-level a11y guide yet; Primer's guidance (which discourages toasts) is the referenced model.
- [#4986](https://github.com/mui/base-ui/issues/4986) (open): toasts queued via a global manager before the Provider mounts are silently dropped (islands/late-mounting shells).
- [#3952](https://github.com/mui/base-ui/issues/3952): `type` is a free string, not a literal union; a typed-manager generic is the planned future direction, not yet built.
- [#4234](https://github.com/mui/base-ui/issues/4234) (open): every component calling `useToastManager()` re-renders on any toast change; a `useToastActions` split was proposed ([#4233](https://github.com/mui/base-ui/pull/4233)) but not merged.
- [#4402](https://github.com/mui/base-ui/issues/4402) (open): logical (`inline-start`/`inline-end`) `swipeDirection` values for RTL are an open discussion, not implemented.
